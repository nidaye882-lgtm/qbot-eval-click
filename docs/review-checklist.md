# Click 代码评审规范

按 PR 的 base 和 head 对照 diff，再检查受影响的调用者、测试和文档。以当前仓库的兼容性约定和实际行为为准。

## 核对要点

- CLI 行为：核对参数解析、默认值和显式输入、错误信息、退出码以及 stdout/stderr。类型转换须保持约定的返回类型和值，特别是枚举、自定义类型和回调接收到的值。
- 一致性：改动参数类型或规范化规则时，检查大小写、Unicode、上下文自定义 token 规范化、帮助和 shell 补全各入口的行为。检查空输入和未匹配输入。
- 兼容性：公开参数和默认行为发生变化时，检查现有调用者、用例和文档。用具体输入说明行为变化及影响范围。
- 测试：行为变化用 CliRunner 或对应单元测试覆盖正常、失败和边界路径。选跑相关 tests/test_options.py、tests/test_types/test_Choice.py 或 tests/test_shell_completion.py。区分实际测试结果和代码推断。
- 维护性：沿用仓库现有的类型标注、辅助函数和测试结构。格式细节只有在影响可读性或违反项目检查时才提及。

## Review 写法

- 对每个实际问题给出严重级别、diff 文件和行号、触发输入、预期与实际行为以及可操作的修复或测试建议。
- 以拟评审的 head 提交为准，概述测试范围、主要问题与结论。未发现阻断问题时给出对应结论并说明检查范围。
- 优先反馈可证实的回归。无法核实的观察以待验证问题记录。
